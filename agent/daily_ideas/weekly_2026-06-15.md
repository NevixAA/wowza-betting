### a) Squad Attack/Defense Aggregation

**Current state:** `home_attack_str` and `away_attack_str` (combined 17.1% feature importance) are computed from team-level rolling goals averages. They average all matches regardless of which players actually participated.

**Proposal:** Replace or augment with confirmed-starter-weighted composite.

```python
def build_squad_features(
    home_team: str,
    away_team: str,
    history_df,  # player_history.parquet loaded as DataFrame
    n_games: int = 5,
) -> dict:
    """
    Aggregate rolling player stats across the confirmed XI into team composites.
    Requires player_history.parquet columns: team, goals_pg, sot_pg, minutes_pg, started.
    Uses only confirmed starters (started=1) to avoid sub-bias.
    """
    features = {}
    for team_name, prefix in [(home_team, "home"), (away_team, "away")]:
        team_rows = history_df[history_df["team"] == team_name].copy()
        # Only use recent starters (last n_games games per player, started only)
        starters = team_rows[team_rows["started"] == 1].copy()
        starters = starters.sort_values("date").groupby("player_id").tail(n_games)

        # Aggregate across confirmed XI — sum (not mean) since squad scoring is additive
        squad_goals_pg = starters.groupby("player_id")["goals_pg"].mean().sum()
        squad_sot_pg   = starters.groupby("player_id")["sot_pg"].mean().sum()

        features[f"{prefix}_squad_goals_pg"] = round(squad_goals_pg, 4)
        features[f"{prefix}_squad_sot_pg"]   = round(squad_sot_pg,   4)

    return features
```

**Does this add signal beyond team rolling averages?**

Tentatively YES, with important caveats:
- Current `home_attack_str` implicitly includes all players who appeared, including subs. Squad aggregation from confirmed starters isolates starting XI quality.
- The signal is only additive when lineup confirmation arrives (T-1h). Pre-lineup, this feature cannot be computed and falls back to the team average.
- **Risk of multicollinearity**: `home_squad_goals_pg` will be highly correlated with `home_attack_str` (~0.85+ expected). Adding both may inflate variance without adding AUC. Use as a **replacement** for `home_attack_str` when confirmed lineup is available, not an addition.
- **Data availability bottleneck**: player_history.parquet currently covers only 3 active leagues. For all 20 ENABLED_LEAGUES, this feature would be N/A during training, making it usable only as an enrichment flag, not a core model feature.

### b) Key Player Absence Indicator

**Definition:** A player is a "key player" if they rank top-2 in `goals_pg` for their team in the current season data within `player_history.parquet`.

**Proposed features:** `key_player_absent_home` (bool), `key_player_absent_away` (bool)

**Formula — attack strength adjustment when key player absent:**

```python
def get_key_player_absent_adjustment(team: str, history_df, absent_player_id: int) -> float:
    """
    Returns multiplicative adjustment to home_attack_str when key player is absent.
    Logic: a team's attack_str should be reduced proportionally to the key player's
    share of team goals in the last N games.
    """
    team_rows = history_df[history_df["team"] == team].sort_values("date").tail(50)
    team_goals_pg = team_rows.groupby("player_id")["goals"].mean()
    total_team_goals = team_goals_pg.sum()

    if absent_player_id not in team_goals_pg.index or total_team_goals == 0:
        return 1.0  # unknown player — no adjustment

    absent_goals_share = team_goals_pg[absent_player_id] / total_team_goals
    # Reduction is proportional to the player's share, capped at 30% drop
    return max(1.0 - absent_goals_share, 0.70)

# Example: Erling Haaland responsible for 40% of Norway's goals
#   adjustment = max(1 - 0.40, 0.70) = 0.70
#   new_home_attack_str = home_attack_str * 0.70
```

### c) Rolling Form Composite (Current Form of All Starters)

**Proposal:** `home_squad_form_last5` = weighted mean of `goals_pg` (last 5 matches) across confirmed XI.

```python
def build_squad_form_composite(
    home_team: str,
    away_team: str,
    history_df,
    confirmed_xi_home: list = None,  # list of player_ids; None = use all starters
    confirmed_xi_away: list = None,
    n: int = 5,
) -> dict:
    """
    Rolling form composite: weighted mean of player goals_pg across confirmed/probable XI.
    starter weight=1.0, sub weight=0.5 (to handle lineup uncertainty pre-confirmation).
    """
    features = {}
    for team_name, xi, prefix in [
        (home_team, confirmed_xi_home, "home"),
        (away_team, confirmed_xi_away, "away"),
    ]:
        team_rows = history_df[
            (history_df["team"] == team_name) &
            (history_df["started"] == 1)
        ].sort_values("date")

        if xi is not None:
            # Post-lineup: use confirmed starters only at weight 1.0
            relevant = team_rows[team_rows["player_id"].isin(xi)]
            weight = 1.0
        else:
            # Pre-lineup: use likely starters (started in >50% of last N games)
            starter_rate = (
                team_rows.groupby("player_id")["started"]
                .apply(lambda x: x.tail(n).mean())
            )
            likely_starters = starter_rate[starter_rate >= 0.5].index
            relevant = team_rows[team_rows["player_id"].isin(likely_starters)]
            weight = 0.5  # uncertainty discount for probable XI

        # Per-player rolling mean over last 5 games
        player_form = (
            relevant.groupby("player_id")["goals"]
            .apply(lambda x: x.tail(n).mean())
        )
        squad_composite = float(player_form.sum() * weight) if not player_form.empty else 0.0
        features[f"{prefix}_squad_form_last5"] = round(squad_composite, 4)

    return features
```

**Data Volume for Training/Validation:**

- player_history.parquet: 30,083 rows
- With 11 starters per team and 2 teams per match, each fixture generates 22 player rows
- Available fixtures: 30,083 / 22 ≈ 1,365 fixtures
- With an 80/20 train/test split: ~1,092 training fixtures, ~273 test fixtures
- **Assessment: INSUFFICIENT for gradient estimation.** The O/U model trains on 15,130 match rows. Adding a feature that requires player_history for only ~1,365 matches means it would be missing for 91% of training data — forcing imputation with league averages, which defeats its purpose.
- **For reliable gradient estimates, we need at minimum 5,000 fixtures with full player coverage.** This requires extending player_history collection to all ENABLED_LEAGUES for multiple seasons.
